Review this code for potential issues, including:

## Architecture & Design
- **Hexagonal Architecture violations**: Domain layer should have NO framework dependencies (no Spring annotations, no JPA imports). Application use cases should depend only on domain interfaces, not on adapter classes.
- **Port/Interface segregation**: Repository and external API interfaces should be in the domain layer; implementations in the adapter layer.
- **Use case boundaries**: Each use case should have a single responsibility. Input/output DTOs should be in the `application/{feature}/dto/` package.
- **Entity factory methods**: Domain entities use `create()` for new instances and `restore()` for persistence reconstruction — ensure these patterns are followed consistently.

## Security
- **JWT handling**: Tokens generated by `JwtTokenProvider` should include proper claims and expiration. The filter (`JwtAuthenticationFilter`) must correctly extract and validate tokens.
- **Authentication checks**: Protected endpoints (like `/user-books/**`) require authentication. Verify that `AuthenticatedUser` is properly extracted from `Authentication.getPrincipal()`.
- **Password encoding**: Passwords should always be hashed with `BCryptPasswordEncoder` before persisting. The encoding should happen in the adapter layer, not the domain.
- **CORS configuration**: `CorsConfig` should restrict origins in production.

## Data / Persistence
- **N+1 queries**: Watch for lazy loading in JPA entity relationships — `BookEntity` ↔ `AuthorEntity` should use `JOIN FETCH` or `@EntityGraph` where needed.
- **Mapper completeness**: Domain-to-entity mappers (e.g., `BookMapper`) should correctly map all fields including collections of authors.
- **Transaction management**: Methods that perform multiple writes (e.g., `CreateBookUseCase.processBook()`) should use `@Transactional`.
- **Flyway vs DDL-auto**: Flyway is disabled by default; if enabled, ensure migrations match the JPA entity model.

## Error Handling
- **Domain exceptions**: Business rule violations should throw domain-specific exceptions (e.g., `InvalidBookException`, `DuplicateUserBooksException`).
- **Global exception handler**: `GlobalExceptionHandler` should map domain exceptions to appropriate HTTP status codes consistently.
- **Edge cases**: Consider empty search results, duplicate entries, invalid status transitions in `UserBooks`.

## Gutendex Sync
- **Rate limiting**: The sync job uses `Thread.sleep(500ms)` between pages — confirm this is adequate for the external API.
- **Duplicate prevention**: `CreateBookUseCase` checks `existsByGutendexId()` before creating a book.
- **Async execution**: The sync runs on a single-thread executor (`gutendexSyncExecutor`) with no queue — concurrent requests return HTTP 429.
- **Error resilience**: Individual book failures should not stop the entire page sync.

## Testing
- **Coverage**: Aim for high coverage on domain entities and use cases. Integration tests should cover controller endpoints.
- **Test isolation**: Unit tests should not load Spring context. Use mocks/stubs for dependencies.
- **H2 compatibility**: Ensure JPA queries and native SQL work with H2 in test profile.

## Code Quality
- **Null safety**: Use `Objects.requireNonNull()` or `Optional` for parameters that should never be null.
- **Immutable collections**: Domain entities return `Collections.unmodifiableSet()` / unmodifiable lists for internal collections.
- **Logging**: Use SLF4J with parameterized logging (`log.info("value {}", x)`) — avoid string concatenation.
- **Magic numbers/strings**: Extract constants for repeated values (e.g., pagination limits, status labels).

## Scripts & Deployment
- **Hardcoded credentials**: The `scripts/deploy-backend-only.sh` contains plaintext DB credentials — these should be injected via environment variables or AWS Parameter Store.
- **Dockerfile**: Confirm the multi-stage build produces a minimal production image.
